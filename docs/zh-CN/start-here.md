# 从这里开始：你的第一个开源 PR

**只做一件事：为一个真实问题建立可以检查的工程记录。** 不要求你一开始就能合并 PR，更不要求先懂 ROCm 或 C++。

## 你将在十篇教程后获得什么？

你应能独立完成：找到真实 Issue → 复现问题 → 调查根因 → 最小修复 → 测试验证 → 发起 PR → 整理 Review → 判断 CI → 收尾。上游是否合并由维护者决定，不受作者、课程或 AI 控制。

## 新手最容易踩的三个坑

1. **选择太大的 Issue**：优先选错误清晰、范围小、维护者认可、无重复 PR 的任务。
2. **AI 说修好就认为修好**：保存命令、日志、环境和 Commit；建立复现前后对照。
3. **还未理解代码就提交**：你要能够向维护者解释每一处修改与测试结论。

## 开始之前的四个检查

- [ ] 我有 GitHub 账号，可以阅读 Issue 与 PR。
- [ ] 我能运行终端（Windows PowerShell、macOS Terminal 或 Linux shell 均可）。
- [ ] 我可以使用一个 AI 编程助手；没有也可手动完成练习。
- [ ] 我已准备一个文件夹记录学习日志，**不会提交密钥、个人数据或无法公开的日志**。

## 学习方法

每课保持固定节奏：**这个问题是什么 → 为什么这样解决 → 真实案例 → 实际操作 → 验收标准**。从第二课开始，复用前一课的输出。每课附一条 CodeX 任务提示词，可作为起点，但执行命令前仍由你审阅。

### 可以没有 GPU 吗？

可以。文档、安装脚本、简单软件 Bug 都不需要 GPU。若你选择 GPU 问题，请先读[云端 GPU 实验室](cloud-gpu-lab.md)。云上 Linux 结果不能自动代表 Windows、本地特定驱动或另一种 GPU 架构的结果。

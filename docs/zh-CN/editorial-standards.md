# 内容与工程质量标准

面向改进本课程的贡献者。[English version](../en/editorial-standards.md)

## 原则

**初学者优先**：术语首次出现需解释用途；先问题、再方法、后细节。
**一课一目标**：每课恰好一个核心技能与可检查输出。
**案例真实**：PR、Issue、Reviewer 话语有原链接；引用不得断章取义。
**范围诚实**：区分 PASS / FAIL / SKIP / NOT RUN；不同 OS/GPU/精度不能相互代替。
**人负责质量**：AI 可以建议、分析、写代码，但用户审阅并决定发布。
**尊重维护者**：先阅读仓库贡献规范；不批量制造 AI PR，不刷评论、不催合并。

## 每课验收清单

- [ ] 开头提出一个新手能感知的具体问题。
- [ ] 明确「今天只学会什么」。
- [ ] 有真实案例锚点（不是只靠成功故事）。
- [ ] 有简短行动步骤和一条可复制的 AI 提示词。
- [ ] 给出一个可以提交或展示的成果模板。
- [ ] 明确前置条件和不能推断的结论。
- [ ] 文末导航齐全：上一课 / 下一课 / 目录 / 另一语言版本。

## Markdown 与链接规范

使用相对链接连接仓库内 Markdown；外部链接使用真实公开 URL。示例地址、SSH 主机和令牌必须用明显占位符；不得示范粘贴凭据。命令注明平台；读者应能在复制前判断其效果。

## 双语对等

英文版与中文版是结构对等的伙伴：同样的课程、同样的成果模板、同样的证据链接、同样的边界。内容修正须在同一变更中覆盖两种语言。提交前运行 `node scripts/validate-docs.mjs`——它检查文件对等、结构与内部链接；翻译的语义质量仍由人工审阅负责。

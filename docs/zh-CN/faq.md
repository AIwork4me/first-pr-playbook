# 常见问题 FAQ

**Q：不会 C++，还可以参与国际开源吗？** 当然可以。先尝试熟悉软件的文档、复现示例、测试用例或简单 Python 修复。但文档更改同样需要遵守原项目规范。

**Q：必须用 CodeX 吗？** 不必。任务提示词可迁移到其他编程助手，也可以手动完成。你始终负责理解、审查、验证和最终提交。

**Q：必须有 GPU 吗？** 不必。只有 GPU 相关 Issue 才可能需要。若使用云 GPU，先确认问题的 OS、GPU 架构、依赖版本是否匹配。见[云端 GPU 实验室](cloud-gpu-lab.md)。

**Q：为什么我复现不出来？** 先核对软件版本、系统、输入、精度、GPU 型号、缓存以及是否真正运行到报错路径。记录「未复现」而不是编造失败结果。

**Q：一个 PR 可以同时修五个问题吗？** 通常不建议新手这样做。把一个可独立解释、可独立测试的修复作为一个 PR，更易审阅。

**Q：Issue 没人回复，我可以直接提 PR 吗？** 先检查项目贡献规范及重复 PR；对复杂设计最好先讨论，小而明确的问题可按项目习惯提交。不要连续催促维护者。

**Q：Review 意见我不同意怎么办？** 给出理由、权衡与验证证据，礼貌讨论。不要为了「绿色」无条件照做，也不要把争议当作人身冲突。

**Q：CI 失败就是我的代码错了吗？** 不一定。先判断失败的是源码、测试、基础环境、权限还是上游已有问题，并保存证据。[第 09 课](../../lessons/zh-CN/09-debug-ci.md)。

**Q：按照课程操作一定能 Merge 吗？** 不能保证。Merge 是项目维护者的决定。即使未合并，规范的 Issue/RCA/PR/Review 记录仍是有价值的能力证明。

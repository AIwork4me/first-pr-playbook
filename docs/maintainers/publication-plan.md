# 微信公众号十篇连载编辑计划（维护者内部文档）

> Maintainer note (2026-10-27): this plan governs the WeChat serialization of the Chinese lessons, not the GitHub course structure. Lesson sources now live in `lessons/zh-CN/`; serialization links should point there.

## 总标题

《跟我学：从零开始，向国际顶级开源项目提交你的第一个 PR！》

## 节奏

建议每周两篇、五周发布第一季。每篇**只讲清一个问题**，正文优先 900–1400 汉字，带较多操作图时可以更长。优先真实证据图：Issue、错误日志、Patch、Review、CI、Merged；不使用来源不清的图片。

## 前情引用原则

- 第 01 篇：独立开篇，给出整套课程入口。
- 第 02 篇：1 段话复用第 01 篇的 Issue 选择卡。
- 第 03 篇：仅引用第 01 篇的选题与第 02 篇的错误日志。
- 第 04–10 篇：正文只回顾上一步必需的成果；文末始终显示此前全部已发布文章目录，避免反复全文介绍。
- 发布前把尚未上线的微信文章链接保留为 `待发布`，绝不使用虚假微信地址。Markdown 源文件链接可先使用仓库相对路径。

## 一篇文章的手机阅读结构

1. 读者今天遇到的一个问题（前 150 字内）。
2. 本文唯一核心 Aha（一句话）。
3. 从 ROCm #13437 抽一个对应的真实证据。
4. 读者实际操作：3–5 步与最小提示词。
5. 验收标准：如何知道自己真的学会。
6. 下一篇预告 + 系列目录链接。

## 传播不是牺牲真实性

标题可以吸引人，但不得暗示读者按照教程必然合并 PR；不得把 fp32 YOLO 一轮训练写成 AMP 训练成功；不得把 Linux 云端验证当作 Windows 全面支持的证据。

## 素材编辑清单

- [ ] 截图与链接指向公开原始证据。
- [ ] 所有命令都标记其运行环境与前置条件。
- [ ] 每篇只有一个教学目标、一份独立成果。
- [ ] CodeX 提示词含有验证及权限边界。
- [ ] 导航链接与文章发布状态同步。
- [ ] 如摘录第三方代码/截图，遵守版权与许可。

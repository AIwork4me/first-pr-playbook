# Mission 04｜最小 Patch Plan

[第 04 课](../../lessons/zh-CN/04-minimal-patch.md) · [模板：Patch Plan](../../templates/zh-CN/patch-plan.md) · [English version](../en/mission-04-minimal-patch.md)

**任务.** 为已确认的根因设计最小必要补丁——先出计划，人类批准后才编码，并保持 diff 最小。

**背景.** Reviewer 用维护成本为每一行多余代码定价。助手只提方案；任何代码存在之前，范围先经人类批准。

**输入.** 带证据的已确认 RCA；目标仓库的惯例与现有测试。

**约束.**

- 先调研仓库中同类修复的已有实现；复用项目惯例与测试框架。
- 比较至少两种修复方案（范围、兼容性、维护成本、回归风险），推荐最小必要变更。
- 计划必须附带明确的 Non-goals 清单。
- 编码后：给出 `git diff --stat` 和逐文件 diff；标出并回退一切与根因无关的改动。
- 不推送、不开 PR。

**步骤.**

1. 调研仓库如何解决这类问题（模式、测试、命名）。
2. 起草逐文件 Patch Plan + Non-goals；等待人类审阅。
3. 批准后在分支上实现。
4. 带人类逐块读 diff，直到能复述每一处改动。

**验证.** 每个改动块都能回答「根因的哪一条要求了它」；计划中的回归测试存在且能运行。

**交付.** 完整的 [Patch Plan](../../templates/zh-CN/patch-plan.md) + 最小可用 diff。

**停止条件.** 若根因的证据比预想薄弱，停下并返回 Mission 03；若最小修复需要项目指南明确拒绝的设计，停下并向人类总结冲突，而不是即兴发挥。

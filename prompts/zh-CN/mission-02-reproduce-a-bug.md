# Mission 02｜构建最小复现

[第 02 课](../../lessons/zh-CN/02-reproduce-a-bug.md) · [模板：最小复现报告](../../templates/zh-CN/bug-reproduction.md) · [English version](../en/mission-02-reproduce-a-bug.md)

**任务.** 在记录好的环境中复现选定 Issue，并缩减为最小、稳定的复现程序——或产出诚实的 NOT REPRODUCED / BLOCKED 记录。

**背景.** 任何人修复之前，必须先证明故障存在。助手负责规划；每次执行由人类批准。

**输入.** `[ISSUE_URL]` 及其记载的步骤；人类的机器（OS、版本、硬件）。

**约束.**

- 先运行原始、未经修改的代码和对应版本。
- 每条命令执行前说明影响；不安装来路不明的脚本；保持系统环境干净（支持时用虚拟环境/容器）。
- 记录 OS、依赖、GPU/驱动（如适用）、Commit SHA、全部命令和完整错误输出。
- 每次删减后重测；绝不为了变短而丢掉触发条件。

**步骤.**

1. 从 Issue 提取可验证的复现步骤与环境要求，形成简短、安全的执行计划供人类审阅。
2. 执行原始步骤；捕获完整日志。
3. 逐步缩减，每删一步重跑一次，保持同一错误签名。
4. 重复运行确认稳定性；记录缓存与种子（如相关）。
5. 将结果标注为 REPRODUCED / NOT REPRODUCED / BLOCKED。

**验证.** 缩减后错误签名不变；第二次运行仍复现；环境身份与日志存放位置已记录。

**交付.** 复现脚本 + 真实日志 + 完整的[复现报告](../../templates/zh-CN/bug-reproduction.md)。

**停止条件.** 所需环境（OS、GPU、驱动、凭据）不具备时停下并标注 BLOCKED——精确记录缺什么。「未复现」永远不能说成「Bug 不存在」；绝不通过改版本号强行制造失败。

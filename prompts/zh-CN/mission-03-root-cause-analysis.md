# Mission 03｜Root Cause Analysis

[第 03 课](../../lessons/zh-CN/03-root-cause-analysis.md) · [模板：RCA 记录](../../templates/zh-CN/rca.md) · [English version](../en/mission-03-root-cause-analysis.md)

**任务.** 用可反驳的实验，把已复现故障的「已证实根因」与「假设」区分开——全程不改源代码。

**背景.** 报错行通常是故障浮现的位置，不是原因所在的位置。助手负责结构化调查；实验在人类已记录的环境上运行。

**输入.** Mission 02 的已验证复现程序、日志与环境记录。

**约束.**

- 每句话显式标注为「观察事实」或「推断」。
- 得出任何结论前，先提出至少两个可反驳的假设（H1、H2……）。
- 每次实验只改一个变量；每个假设配最小的区分实验与预期结果。
- 证据足以解释原始错误之前，不改源码、不宣布「根因已确认」。

**步骤.**

1. 把调用链从入口到最深失败模块分层，标注信息在哪里变得更具体。
2. 起草假设表与区分实验，交人类执行。
3. 结果到达后，把每个假设标为 CONFIRMED / REJECTED / UNKNOWN，并附日志指针。
4. 陈述已证实根因、未验证部分，以及为什么在症状处打补丁是错的。

**验证.** 根因结论能解释原始错误签名；且在竞争假设下，至少一个实验结果会不同。

**交付.** 带证据表的完整 [RCA 记录](../../templates/zh-CN/rca.md)。

**停止条件.** 实验无法区分假设时，诚实报告 UNKNOWN；不允许用助手的自信替代证据；没有站得住的根因，不进入补丁阶段。

# Mission 05｜真实 A/B 与回归验证

[第 05 课](../../lessons/zh-CN/05-prove-the-fix.md) · [模板：验证矩阵](../../templates/zh-CN/validation-matrix.md) · [English version](../en/mission-05-prove-the-fix.md)

**任务.** 设计并执行可重复的 Baseline（未修复）vs. Patched（修复后）对照（含回归测试），并诚实记录每一项结果。

**背景.** 「现在能跑了」不是验证。证据必须能让一个怀疑者亲自重跑。

**输入.** 修复分支；基线 Commit；原始 Issue 的复现程序与真实负载。

**约束.**

- 固定可比较的输入与环境，唯一变量是补丁；记录两个 SHA。
- 先验证基线可重现原始错误，再运行修复侧与回归测试。
- 每项标为 PASS / FAIL / SKIP / NOT RUN / EXPECTED_FAIL；绝不把 SKIP 算作 PASS。
- 说明缓存与数值有效性：编译缓存是否重建/绕过；浮点差异是否在公差内。
- 给出最窄的可支持结论，以及未测试的 OS/GPU/精度/负载清单。

**步骤.**

1. 设计矩阵：基线复现、修复后同输入检查、新增回归测试、相关既有测试、受影响真实负载。
2. 按此顺序执行，保存命令、版本、退出状态与日志位置。
3. 填写[验证矩阵](../../templates/zh-CN/validation-matrix.md)；最后写限制行。

**验证.** 基线出现原始失败；修复后同输入通过；回归测试在基线上红、修复后绿（或注明 SKIP 原因）。

**交付.** 附真实日志的验证矩阵。

**停止条件.** 基线无法复现时停下（先修环境——没有失败基线的对照什么都证明不了）；任何结果与修复假设冲突时停下报告，而不是把它揉成 PASS。

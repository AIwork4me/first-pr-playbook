# Mission 10｜Merge 导向收尾与作品集

[第 10 课](../../lessons/zh-CN/10-merge-and-handoff.md) · [模板：作品集记录](../../templates/zh-CN/portfolio-handoff.md) · [English version](../en/mission-10-merge-and-handoff.md)

**任务.** 审计 PR 的真实就绪状态，起草一条礼貌、不催促的收尾评论，并整理一份证据完整的开源作品集记录——使用 GitHub 的真实状态，无论它是什么。

**背景.** 专业收尾意味着维护者一眼看清哪些已就绪、哪些仍有风险，且不承受你的压力。耐用的资产是记录本身，与是否合并无关。

**输入.** PR URL；其 Review 线程、检查与描述；Mission 01–09 的成果。

**约束.**

- 核对当前 HEAD、描述一致性、未解决的实质性评论、该 HEAD 上的必需检查。
- 从 GitHub 读取 PR 真实状态：open / approved / merged / closed without merge。绝不假设未合并的 PR 已 Merge。
- 收尾评论保持草稿；由人类决定是否发布。
- 作品集如实记录未验证项与人类亲自做出的工程决策；注明 AI 协助，但重点是所有权。

**步骤.**

1. 运行就绪审计；诚实列出缺口。
2. 起草两三段的收尾评论（关键修改、证据位置、局限、如有的请求）。
3. 查证并记录 PR 的实际状态与日期。
4. 整理[作品集记录](../../templates/zh-CN/portfolio-handoff.md)：问题、复现、RCA、最小设计、验证、协作、结果、局限、个人决策。

**验证.** 第三方能凭链接核实作品集的每一条主张；记录中的 PR 状态与 GitHub 当日一致。

**交付.** 作品集记录 + 收尾评论草稿。

**停止条件.** 必需检查仍在运行时停下（报告 PENDING 而不是猜测）；若 PR 被关闭未合并，记录维护者的理由后停下——不起草重开或同内容替换 PR。
